Issues to address
CriticalEmil

No prefers-reduced-motion guard anywhere in the document

WhatA full-text search for prefers-reduced-motion across the file returns zero matches. Every transition and the two @keyframes loops (syncPulse, jumpHighlightFlash) run unconditionally.

Why it mattersThis is the one accessibility requirement the skill treats as non-negotiable regardless of how minimal the motion budget already is — vestibular-sensitive users have no way to suppress even this app's restrained motion.

Recommended motionAdd a single global guard near the top of the stylesheet collapsing all durations to near-zero while preserving final states, per the standard pattern. This is a one-time, file-wide addition — not a per-component fix.

CriticalEmil

Modal open/close is a hard display:none/grid cut

What.modal-backdrop toggles display: none → display: grid via the .show class with no transition at all — used by at least four modals (report modal, line-detail, picker, backup).

Why it mattersThe app's own override file names "drawer/modal open-close" explicitly as a real state change worth animating — this is a motion gap in primary UI, the same category the drawer and toast already got right.

Recommended motionBorder/background-only, no shadow, no blur: backdrop opacity 0→1 at 150ms ease-out entrance / 120ms ease-in exit; panel opacity + translateY(8px)→0 at 180ms ease-out entrance / 140ms ease-in exit — mirroring the fix already applied to .sdrawer/.toast (distinct easing per direction, not one curve reused both ways).

Inventory library panel expand/collapse is instant

What.inventory-library switches display: none → block on .open with no transition — a source-catalog panel that expands under a toolbar button, structurally identical to the drawer and modal cases above.

Why it mattersSame motion-gap category as the modal: a real state change (expanding a settings/library panel) that currently snaps while its siblings (drawer, toast, sidebar) all animate.

Recommended motionReveal via clip-path: inset() rather than height (avoids layout thrash on the surrounding grid): 180ms ease-out to open, 140ms ease-in to close — distinct curves per direction, same as the other real-state-change fixes in this report.

ImportantEmil

Two clickable state toggles skip the shared timing scale entirely

What.slide-thumb and .display-layout-tab both change border/background/color on .active, but neither base rule declares a transition — every sibling toggle in the app (.nav-item, .prospect-row, .club-card, .legend-row) does.

Why it mattersThe override file calls this out by name: "inconsistent transition durations across near-identical elements — pull from one timing scale, not ad hoc values per component." These two just have none at all, which reads as more jarring than an inconsistent value would.

Recommended motionAdd transition: border-color 140ms, background 140ms, color 140ms; to both base rules — matching value, not a new one, since this is a state toggle rather than an entrance/exit.
